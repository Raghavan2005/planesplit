## Open gaps

None remaining in R1–R13 or Q1–Q3. Two real bugs were found and fixed while closing Q2 (see below) — recorded here rather than silently folded into "was always fine," per CLAUDE.md §2's rule against silently removing/hiding requirement gaps:

- ~~No requirement yet defines the exact grace-window duration~~ — **closed**: `GRACE_WINDOW_SECONDS = 2.0` is declared once in `faults/update_channel.py::UpdateChannel` and imported everywhere else that needs it (`verify/verifier.py`).
- ~~R1–R13 all show Status "Planned"~~ — **closed**: every row re-verified against the actual implementation and test suite and updated to **Done** with real file/test references, replacing stale planning-time citations.
- ~~Q2 malformed/duplicate/out-of-order input untested~~ — **closed**, and closing it surfaced two real bugs, both fixed: (1) `Network._trace()` silently returned an empty/truncated path for a broken topology reference (unregistered attachment or next-hop router id) instead of raising — now raises `ValueError` immediately. (2) `Verifier.push_legitimate_change()` had no protection against an out-of-order/stale call moving the grace-window timestamp backwards, which could shrink a flow's window and produce a false-positive alert — now ignores any call whose `now` is older than the flow's current recorded change. See `test_negative_cases.py`.
